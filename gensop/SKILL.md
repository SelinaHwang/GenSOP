# GenSOP

Use the host agent's own model to generate the SOP. Do not call Kimi, another model API, or any external service, and do not ask for an API key.

## Runtime and installation

This skill needs Python 3.10 or newer and only the Python standard library. Resolve all resources relative to this `SKILL.md`; do not depend on a project-specific absolute path.

Install the complete `gensop` folder through the host's supported Skill installation mechanism. Keep `SKILL.md`, `references/`, and `scripts/` together; do not extract or relocate individual files after installation.

## Required workflow

1. Treat the user's natural-language request, after trimming outer whitespace, as the generation input. It must contain 1–500 Unicode code points.
2. Read `@references/generation-policy.md` completely and use the system Prompt inside its `text` block without semantic changes. Generate exactly one response object with the host model, following that rule set and response contract. Do not expose internal reasoning.
3. Save the trimmed request as UTF-8 text and the response as UTF-8 JSON in a per-request working directory outside the installed skill folder.
4. Run `scripts/gensop.py prepare` with the request, response, state, and preview paths. The script validates deterministic constraints and creates the readable preview. Do not treat a successful deterministic check as proof that the goal, order, granularity, labels, timing rationale, or refusal judgment is semantically correct; those remain model judgment under the generation rules.
5. If the response is `refuse`, present its fixed reason messages and stop. Never confirm or export a refusal.
6. If the response is `generate`, present the complete readable preview and ask the user to explicitly confirm it or request changes. Do not infer confirmation from silence, an earlier request to create an SOP, or approval of a different version.
7. When the user requests any content change, generate a complete replacement response with the host model, run `prepare` again, and show the new preview. This resets confirmation. The deterministic script never truncates, fills, rewrites, or repairs model content.
8. Only after the user explicitly confirms the currently displayed preview, run `scripts/gensop.py confirm` on its state file, then run `scripts/gensop.py export`. Do not call the model or change the response between confirmation and export.
9. Return the new file path. The exporter uses the confirmed `sopData` unchanged, verifies it again, wraps it as one SOPower Share envelope, checks UTF-8 size, and refuses to overwrite an existing file.

Example commands, with paths chosen for the current request:

```text
python <skill-root>/scripts/gensop.py prepare --request <request.txt> --response <response.json> --state <state.json> --preview <preview.md>
python <skill-root>/scripts/gensop.py confirm --state <state.json>
python <skill-root>/scripts/gensop.py export --state <state.json> --output-dir <output-directory>
```

## Boundaries

- Read `@references/sopower-file-contract.md` when explaining validation, compatibility, or export structure.
- A step generated by this skill must be at least 60 seconds and its name at most 8 Unicode code points. These are GenSOP generation requirements. SOPower itself accepts 1–86400 seconds and step names up to 60 Unicode code points; do not mislabel the stricter generation requirements as SOPower import limits.
- Keep semantic checks in the host-model layer. Never claim that the deterministic script verified the SOP's goal alignment, stage order, granularity, label meaning, factual grounding, or safety judgment.
- Export only a single `.sop.json` Share file. Do not generate a full backup, template envelope, server record, or additional sidecar inside the export.
- Working request, response, state, and preview files are local workflow artifacts. Do not package evaluation runners, score sheets, case banks, historical model responses, credentials, or machine-specific paths with this skill.
